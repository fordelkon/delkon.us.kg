[LeetCode 62. 不同路径](https://leetcode.cn/problems/unique-paths/)给定 $m$ 行、$n$ 列的网格，机器人从左上角出发，每次只能向右或向下移动一步，要求返回到达右下角的路径总数。例如 $m=3,n=2$ 时，把两步向下和一步向右排列，可得到 3 条路径。题目保证 $1 \le m,n \le 100$，答案不超过 $2\times10^9$。

到达一个格子的最后一步只能来自上方或左方，因此可以逐格累加路径数。若进一步利用每条路径的向下、向右步数固定这一条件，还能直接计算组合数。[《最小路径和：网格累加极值与原地状态覆盖》](/posts/algorithm/minimum-path-sum/)保留了相同移动规则，但目标改为累积权值的最小值，不能只凭步数得到答案。

## 状态定义与边界

定义 $dp[i][j]$ 为从 $(0,0)$ 到格子 $(i,j)$ 的路径数。内部格子的所有路径按最后一步划成互不重叠的两类：从上方进入，或从左方进入，因此：

$$
dp[i][j] = dp[i-1][j] + dp[i][j-1], \qquad i>0,\ j>0.
$$

边界没有两种选择：

- 起点 $dp[0][0]=1$，不移动也算一条路径。
- 首行只能一直向右，$dp[0][j]=1$。
- 首列只能一直向下，$dp[i][0]=1$。

每步都使坐标和 $i+j$ 增加 1，因此状态依赖构成有向无环图。按行从左到右计算时，上方和左方都已求出，是合法的拓扑顺序[^clrs-dag]。这与[《从调用栈理解递归》中的自底向上递推](/posts/understanding-recursion/#从记忆化到自底向上递推)相同：按依赖顺序计算每个状态一次，避免朴素递归重复求解同一格子。朴素分支递归的调用次数可用 $O(2^{m+n})$ 作上界，但单条调用链只有 $O(m+n)$ 层，不能把两种开销混为一谈。

## Python：一行数组保存两行所需的状态

计算 `(i, j)` 时，只需上一行同列与当前行左侧的结果。用一维数组保存状态，按列从左到右更新即可。行列交换不改变路径数，先把较小维度作为数组长度；代码只改变局部整数变量，不修改外部对象：

```python
class Solution:
    def uniquePaths(self, m: int, n: int) -> int:
        m, n = max(m, n), min(m, n)
        dp = [1] * n

        for _ in range(1, m):
            for j in range(1, n):
                # The old dp[j] is above; the updated dp[j - 1] is to the left.
                dp[j] += dp[j - 1]

        return dp[-1]
```

`dp = [1] * n` 初始化首行。每轮不修改 `dp[0]`，保留首列只有一条路径的边界。更新 `dp[j]` 前，该槽位仍是上一行的结果；`dp[j - 1]` 则已经更新为当前行的结果。相加后得到当前格子的路径数，最终 `dp[-1]` 对应终点。

若反过来从右向左更新，左侧槽位仍是上一行的旧值，就不再对应递推式。例如 $m=3,n=3$ 时，计算第二行的错误更新会得到 `[1, 2, 2]`，而正确的第二行应是 `[1, 2, 3]`。

时间为 $O(mn)$，辅助空间为 $O(\min(m,n))$，返回数值占 $O(1)$ 空间。每个中间格子的路径都可以接上一条固定后缀路径到终点，因此状态值不超过最终答案；题目保证答案范围，递推加法也不会超过 32 位有符号整数范围。

## 从固定步数推导组合数

从 $(0,0)$ 到 $(m-1,n-1)$，任何路径都必须向下 $m-1$ 步、向右 $n-1$ 步，总步数固定为：

$$
N=m+n-2.
$$

在这 $N$ 个位置中，选出哪 $m-1$ 个位置向下，剩余位置就全部向右，且每种选择对应唯一一条路径。因此答案为[^concrete-math]：

$$
\binom{m+n-2}{m-1}=\frac{(m+n-2)!}{(m-1)!\,(n-1)!}.
$$

令 $k=\min(m-1,n-1)$，利用组合数对称性，可以只计算 $k$ 步：

$$
\binom{N}{k}=\prod_{i=1}^{k}\frac{N-k+i}{i}.
$$

若 $k=0$，只有一行或一列，答案直接为 1。其余情况用逐步乘除计算，避免先求巨大阶乘。

### 为什么每步都能整除

令 $S_0=1$，第 $i$ 次更新后：

$$
S_i=S_{i-1}\frac{N-k+i}{i}=\binom{N-k+i}{i}, \qquad 1\le i\le k.
$$

右侧是整数，所以代码中的 `ans * (N - k + i) / i` 每一步都能整除，不依赖浮点数近似。必须先乘再除；若先算 `(N - k + i) / i`，整数除法可能提前截断。

### 为什么临时乘积也安全

因为 $N-k\ge k\ge i$，每步的比例 $(N-k+i)/i>1$，状态值递增且不超过最终答案 $2\times10^9$。乘法先于除法，临时值可能更大，但乘数最多为 $N\le198$，因此可用以下宽松上界约束：

$$
S_{i-1}(N-k+i)\le(2\times10^9)\times198=3.96\times10^{11}.
$$

该值远小于 $2^{63}-1$，所以用 64 位 `long long` 保存中间结果足够。若直接求阶乘，连 $21!$ 都已超过有符号 64 位范围，即使最终组合数很小也可能溢出。

## C++：逐步乘除计算组合数

```cpp
#include <algorithm>

class Solution {
public:
    int uniquePaths(int m, int n) {
        const int total_steps = m + n - 2;
        const int k = std::min(m - 1, n - 1);

        // After iteration i, ans equals C(total_steps - k + i, i).
        long long ans = 1;
        for (int i = 1; i <= k; ++i) {
            ans = ans * (total_steps - k + i) / i;
        }

        return static_cast<int>(ans);
    }
};
```

循环执行 $k$ 次，每次做常数次 64 位算术运算。在题目的数值范围内，时间为 $O(\min(m,n))$，辅助空间为 $O(1)$。最终转换回 `int` 由题目保证的答案上界支持。

| 方法       | 时间复杂度     | 辅助空间       | 适用条件                               |
| :--------- | :------------- | :------------- | :------------------------------------- |
| 滚动递推   | $O(mn)$        | $O(\min(m,n))$ | 可以修改转移以处理障碍物等约束         |
| 组合数计算 | $O(\min(m,n))$ | $O(1)$         | 无障碍，路径与向下步的位置选择一一对应 |

加入障碍物后，部分步序会经过禁止格子，这个简单组合公式就不能直接套用；递推则可以把障碍格的路径数设为 0。若改成求最小路径和，如[《最小路径和：网格累加极值与原地状态覆盖》](/posts/algorithm/minimum-path-sum/)，则将前驱计数相加改为比较累积权值，仍可保留同样的扫描顺序。
